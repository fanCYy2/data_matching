# 中国学者匹配 —— 试过的所有方法总清单

> 目的:把到 2026-08-28 为止**所有试过的消歧方法**连同结果、判决、失败原因列全,供拍板。
> 一句话:**召回不是问题(97.7%),病在消歧;而这份数据里"能算出来的判据"全是候选间
> 共享的属性,劈不开"同机构多个同名人",所以高覆盖 + 95% 自动精度到不了。**

---

## 0. 先看懂三个不同的"分母/基线"(否则数字会误读)

不同实验测的人群不同,**百分比不能横向直接比**:

| 口径 | 人群 | argmax 论文数 baseline |
|---|---|---|
| **全量端到端** | 全部 1949 个 gold 行 | **68.3%**(1332/1949) |
| **可解决区** | gold 存活 host 过滤的行(~1664) | **85.9–86.4%** |
| **带 orcid 子样本** | 120 行(有 host 且有带 orcid 候选) | 见 §5,单独一套 |

召回上限:层1 候选召回 **97.7%**;可解决区 gold 在 host = **87.7%**(其余 12.3% 机构数据缺口,救不回)。
**oracle 天花板**:用 gold 自己的(脏)子学科过滤 = **94.1%**,但靠脏标签自洽,外部不可复现。

## 1. 现役流水线(四层)的各层贡献

| 层 | 做法 | 结果(全量,按 source) | 判决 |
|---|---|---|---|
| 层1 姓名 | 中文→拼音变体 exact/alias/fuzzy | 候选召回 97.7% | ✅ 召回够,非瓶颈 |
| 层2 机构闸 | 候选须在该行 host 机构发过文 | `round2_inst`(过滤后唯一)**82.6%**,覆盖 6.2% | ⚠️ 干净但覆盖极小 |
| 层3 语义 v1 | 子学科名×中文领域 bge-m3,过阈值+margin | `round3_semantic` **29.9%**,覆盖 9.1% | ❌ 几乎没用 |
| 层4 兜底 | 论文数 argmax | `round4_maxpapers` **75.3%**(占全量 71%)、`round4_semtie` 60.9% | ⚠️ 兜底,靠论文数硬掰 |

**核心失败模式**:同机构多个同名者,现选论文数最多的,但真人往往论文更少 ——
可解决区 225 个错里 **100%** 是"真人论文数 < 被选中同名者"(中位 271 vs 786)。**高产同名者遮蔽真人。**

## 2. 机构 / 合著类信号(全部 < baseline)

| 方法 | 结果 | vs baseline | 为什么失败 |
|---|---|---|---|
| host 论文数(候选在本机构发文数) | 84.1% | < 86.4% | `institutionid` **40% 边缺失** → 按机构计数系统性漏计 |
| host 合著者数(合作者也在本机构) | 78.8% | < 86.4% | 同上,越机构化越差 |
| last_known_institution 救回丢失 gold | 0/234 | 无效 | — |

**根因(probe 实测)**:`raw_affiliation_string` **整列 100% 空**;`institutionid` **40% 边缺失**。
全局论文数不受这些缺口影响,所以任何"按机构计数"的信号都比不过它。

## 3. 领域 / 内容类信号(全部 regress)

| 方法 | 结果 | vs baseline | 为什么失败 |
|---|---|---|---|
| bge-m3 阈值过滤(子学科名×中文领域,任意 floor) | 60–68% | < 74% | 见下 |
| 离散化 top-K 最近子学科过滤 | 61–64% | < 74% | 见下 |
| **标题内容匹配**(候选真实论文标题×中文领域,bge-m3) | 见下表 | 全 ≤ baseline | 见下 |
| **v2 领域聚类原型**(中文领域文本聚类 × 作者摘要质心,留一验证) | acc@1 38–41%、argmax sim 42–47%、filter 全 ≤ baseline | < 85.9% | 见下 |
| **中文论文存在性**(zh-cn 数量/占比/唯一持有者过滤,2026-08-29) | 69.8–84.1%,全 ≤ baseline | < 85.9% | 见下 |

**标题内容匹配详数**(`validate_title_cn.py`,S=524):

```
baseline argmax papers                 86.5%
argmax title-sim (纯内容排序)           31.3%   ← 灾难
filter title-sim>=0.40/.45/.50/.55/.60  79.2/65.8/71.0/80.3/86.1%   ← 全 ≤ baseline
ORACLE subfield-overlap                 93.9%
判别度:真人 sim mean 0.449(p25 0.414) vs 冒名者 0.404(p75 0.442)  ← 大面积重叠
```

**为什么领域/内容全失败**:
1. OpenAlex 作者**子学科标签本身脏**(高分子材料→被标 Composite material;固体无机化学→被标 AI/数学分析)。
2. bge-m3 **读得懂中文术语**(色谱→Chromatography 对),死因是**目标标签脏**,不是翻译。
3. 换"干净的标题内容"也不行:**判别度≈0**——真人标题-领域相似度只比冒名者高 0.045 且分布重叠,
   跨语种(英文标题×中文领域短语)cosine 被"通用学术英语"淹没,分不出具体子学科。
4. 换"EU/US v2 式同语言内容比较"还是不行(`validate_v2_cn.py`,2026-08-29,全量可解决区 1664 行):
   **原型用 gold 真人的英文摘要质心建(近似 oracle 构造),真人仍只有 ~40% 排第一**。
   领域内容信号在"同机构同名人"内部确实劈不开——共享属性诅咒的第三次实证。

**v2 聚类原型详数**(`validate_v2_cn.py`,全量,1664 行可解决区,123,874 篇摘要,20,761 作者有质心):

```
baseline argmax papers                 1429/1664 = 85.9%
argmax v2-sim(K=50→400)               42.1% → 47.4%   ← 远低于 baseline
filter sim>=0.55..0.75 + papers       83.6–85.8%       ← 全 ≤ baseline
acc@1(候选>=2, K=50→400)              38.2% → 41.3%,ties 全为 0
判别度:gold mean 0.843–0.859 vs nongold 0.739–0.765,gold p25 ≈ nongold p75(重叠大)
```

与标题实验共享同一死因:**均值差存在、但分布重叠;且这是"同簇内比",冒名者与真人在
同一机构、同一大领域,内容本来就像**。方向判死:**领域/内容类信号全部到此为止**,
不再试 floor/阈值/聚类粒度/摘要长度变体。

**中文维度补测**(`probe_zh_cn.py`,2026-08-29,同 1664 可解决区 / 25,887 候选行):

```
baseline argmax papers             1429/1664 = 85.9%
zh>=1..10 + papers                 69.8% → 84.1%   ← 全 ≤ baseline
zh_share>=5%/10%/20% + papers      77.5 / 79.8 / 81.4%
zh>=1 AND en>=1 + papers           70.0%
unique zh>=1 / zh>=3 (auto)        74.6% / 81.5%
filter zh>=1 内 gold 覆盖仅 197/1664 = 11.8%
```

**sciscinet_papertitleabstract 数据事实**(只读实测,122,351,775 行):
- 列 = paperid / title / abstract_inverted_index / language;**无年份、无 DOI、无引用、无机构**。
- gold 作者覆盖 1899/1905 = 99.7%;地址区 25,887 候选行全部可关联到论文(21,106 作者有标题)。
- 全表 zh-cn 366 万篇,其中 96% 是真实中文标题+中文摘要;gold 行 31%(607/1949)有 zh-cn 论文。
- 结论:**内容/语种作为内部判别信号全部判死**;该表剩余价值 = 唯一本地 authorid→论文清单
  来源,供「外部检索锚点」(中文标题+单位+年度搜教师主页/ORCID) 路线使用,与 §6.2 同向。

## 4. 置信度门控(`gate_cn.py`,全量 1949)—— 内部信号封顶

想法:不追全自动,只自动接受"高置信"行,其余人工。扫覆盖率×精度:

| 规则 | 精度 | 覆盖 | 判决 |
|---|---|---|---|
| 全接受(baseline) | 68.3% | 100% | — |
| host 唯一存活(=round2_inst) | 82.6% | 6.2% | 干净但小,且被 40% 缺边钉死 |
| host 唯一 ∧ 也是论文数最大 | 92.9% | 4.3% | 接近但覆盖太小 |
| host 唯一 ∧ exact ∧ n_cand≤20 | **100%** | **0.8%** | 到 95% 但只 15 行 |
| has_host ∧ 论文数最大 ∧ exact | 85.0% | 53.5% | 最大"还行"切片,但不到 95% |
| 论文数 margin ≥100 篇(同机构多同名) | 72.8% | — | **假置信陷阱**:领先 100+ 篇也只 72.8% |

**结论**:内部门控最多 **85%@50% 覆盖** 或 **93%@4% 覆盖**;要 ≥95% 精度,覆盖**掉到 <1%**。

## 5. ORCID 外部键 —— 键很干净,但候选核验被同一堵墙封死

### 5a. ORCID 键干净度(实测,✅)
- gold 真人 **87.2% 有 orcid**;**0 冲突**(无两真人共 orcid);**orcid→authorid 全库 1:1**(零碎片)。
- **理论**:已知本人 orcid → 直接查到唯一 authorid,~99% 精度。**键这侧完美。**

### 5b. 陷阱:orcid 列本身不消歧(⚠️)
- 每行**中位 ~15 个同名候选都各自带 orcid**(15 个不同真人,各有 orcid)。"有没有 orcid"区分不了。
- 缺的不是"候选有无 orcid",而是"**杰青本人的 orcid 是哪个**"——数据集里没有,得外部确定。

### 5c. ORCID 档案填充率(60 个 gold 样本)
```
emp或edu 有机构  51.7%   |  中文名(other-names CJK)  1.7% ← 信号死
emp 50.0%  edu 36.7%    |  country 23.3%  works>0 73.3%(NSFC侧无论文清单,用不上)
```
→ 唯一可用的 NSFC 侧锚点是**机构**;中文名指望不上;works 用不上。

### 5d. 端到端候选核验(`verify_e2e_cn.py`,120 行,抓 3266 个 orcid 的 emp/edu,❌)
补了 OpenAlex institutions 表(319 host,英文名),ORCID 英文机构名↔host 英文名匹配,再和 OpenAlex 取并集:

```
抓取召回(真人在候选集内)  90.0%       带机构 orcid  40.8%
openalex-only unique   93.0% @ 36%
orcid-only  unique     63.0% @ 38%    ← 纯 ORCID 机构匹配噪声大(CAS 各所名互串)
UNION unique           93.0% @ 36%    ← 与 openalex-only 一字不差,ORCID 零增益
UNION +papers          72.6% @ 98%    ← 同 openalex
```

**为什么并集零增益(根本原因,非 bug)**:核心难 case = **同机构多个同名人**,他们本来就**共享**该机构;
机构(无论 OpenAlex 还是 ORCID)对共享属性天生不可分。**故 86.9% 的 ORCID 天花板作废**——
它前提是"认出本人 orcid",而候选核验只能靠共享的机构、劈不开同机构同名者。

## 7. 一页纸总结

- **召回没问题(97.7%),病在消歧。**
- **试过的所有判据——论文数、host 论文数、host 合著、领域标签、离散子学科、标题内容、
  置信度门控、ORCID 机构核验——全部 regress 或封顶。** 它们的共同死因是一句话:

  > **凡是候选之间"共享"的属性(同名 + 常同机构),都不能用来区分他们。**

- **能到 95% 高覆盖的唯一出路,是一个"每人独有、不共享"的外部键**:本人 ORCID(从零找)
  或中文名解析。都需外部数据、都难、搜索时又落回名字+机构歧义。
- **务实可交付(现在就能做)**:分层结果 —— 高置信 auto 子集自动定档 + 其余按难度排序进人工队列;
  用户按精度/覆盖取舍点切一刀。契合项目既有"低产扔人工"哲学。全自动 95% 高覆盖,这份数据给不了。
